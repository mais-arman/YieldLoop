# 4. FIX THE UNWANTED POST-LOGIN REFRESH

The user reports that clicking Sign In causes an automatic full-page refresh before the application pages appear.

Inspect the complete login flow and identify the actual cause before changing it.

Investigate:
- Default browser form submission or missing preventDefault handling.
- Repeated login submissions.
- Hard navigation through window.location, location.href, or window.location.reload.
- Wouter navigation behavior.
- Authentication-state hydration and the current-user query.
- CSRF acquisition and session-cookie establishment.
- React Query cache initialization, invalidation, and stale unauthenticated results.
- Protected-route redirect loops.
- Effects that repeatedly redirect when user/session state changes.
- Incorrect request retries or duplicated login calls.

Fix the underlying defect without weakening session security.

Expected behavior:
1. The user submits valid credentials.
2. The form shows a clear loading state and prevents duplicate submission.
3. The existing secure login and CSRF flow completes.
4. Authenticated identity is retrieved or safely initialized.
5. The application updates authentication state and uses client-side routing to navigate to the appropriate role-specific landing page.
6. The browser does not perform an unnecessary full-document reload.
7. The intended page appears without redirect loops, stale unauthenticated state, or duplicated login requests.

A legitimate short loading period while the session or current-user state is being verified is acceptable; a needless full-page refresh is not.

Do not remove CSRF protection, disable session validation, or hardcode authentication state just to make navigation appear faster.

Add or update tests covering:
- Valid login and client-side navigation.
- Invalid credentials.
- Duplicate submission prevention.
- Current-user state after login.
- Reloading a protected page and restoring an existing valid session.
- Expired/invalid session handling.
- Logout and subsequent protected-route denial.
- Redirect-loop prevention.
- Browser navigation events and unexpected document reloads, where the available test setup supports it.

Report the verified root cause and the exact fix.
