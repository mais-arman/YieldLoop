Implement YieldLoop Phase 2B now: working authentication and role-based access control.

Continue from the existing Phase 1 foundation and Phase 2A schema. Do not restart the project or replace the existing React/Django/PostgreSQL architecture.

Implement:

1. Apply the reviewed authentication schema migrations only to the configured development database after verifying its target and confirming it is not a production database. 2. Implement CSRF acquisition, login, logout, and current-user endpoints under `/api/v1/auth/`.
3. Enforce CSRF protection on login and all unsafe session-authenticated requests. Configure session cookies as HttpOnly, host-only, SameSite=Lax, and Secure when HTTPS is used. Keep the frontend and API same-origin.
4. Implement server-side role authorization for exactly three roles: `cutting_operator`, `production_supervisor`, and `manager`. Never trust a role supplied by the client.

6. Implement secure temporary-password replacement and expiry. Accounts with expired or unreplaced temporary passwords must be restricted to the password-change flow and logout.
7. Prevent self-demotion and protect the last active Manager, including concurrent requests, using a consistent PostgreSQL transaction-scoped lock and rechecking state inside the transaction.
8. Add audit events for sensitive account and role changes without logging credentials, tokens, cookies, or request bodies.
9. Add shared throttling for authentication endpoints that works across multiple Gunicorn workers. Do not use per-process-only throttling.
10. Build the login page and authenticated application shell in React. Support Arabic and English, RTL/LTR, loading states, clear errors, and logout. Display the authenticated user's role. Do not build production jobs, material records, dashboards, or cutting optimization in this phase.
